# Reglas de trabajo

1. El repositorio `nicoKaminski/biticraft` es público. No agregues secretos ni datos privados; usa únicamente nombres de variables y valores ficticios o vacíos en ejemplos.
2. Antes de iniciar, confirma únicamente que estás en el repositorio y la rama indicados por la tarea. Para ello, las únicas comprobaciones Git permitidas son `git rev-parse --show-toplevel` y `git branch --show-current`. La tarea debe identificar repositorio, rama, alcance, planificación, restricciones y validaciones; si falta un dato que impide cumplirla sin riesgo, informa el bloqueo.
3. La rama habitual es `dev`, pero trabaja en la rama que la tarea indique expresamente. `main` requiere un pull request desde cualquier rama.
4. Inspecciona primero los archivos reales, sus consumidores y las configuraciones relacionadas. No supongas que la documentación antigua coincide con la aplicación.
5. Usa subagentes si las responsabilidades pueden separarse en grupos con archivos de escritura exclusivos. Coordina contratos compartidos antes de integrar. Estas reglas, incluidas las restricciones Git y de navegador, se aplican por igual a cada subagente.
6. No cambies comportamiento, diseño ni código fuera del alcance solicitado. No agregues dependencias ni hagas instalaciones o actualizaciones sin autorización.
7. No ejecutes ninguna operación Git aparte de las dos comprobaciones de identidad indicadas en la regla 2. Quedan prohibidas todas las demás operaciones Git, tanto de lectura como de escritura. En particular, no consultes estado, historial, commits, mensajes o hashes, remotos ni sincronización; tampoco hagas staging, commit, push, pull, fetch, merge, rebase, reset, checkout, switch, restore, stash, clean ni operaciones equivalentes. Revisa los cambios propios leyendo directamente los archivos modificados, sin recurrir a Git.
8. Por defecto, no abras ni automatices navegadores. Esto incluye Playwright, Puppeteer y cualquier herramienta equivalente. Se requiere autorización expresa de Nico para usar un navegador en cada tarea; la autorización no se extiende a tareas posteriores. Esta regla también aplica a los subagentes.
9. No ejecutes comandos destructivos ni modifiques archivos que contengan credenciales reales. No leas ni muestres credenciales reales salvo autorización expresa y necesidad directa.
10. Ejecuta solo las validaciones autorizadas. En el informe separa claramente las ejecutadas de las pendientes; no atribuyas un resultado a una validación no ejecutada. No añadas comprobaciones que la tarea no requiere.
11. Antes de finalizar, revisa directamente los archivos modificados y audita el alcance, la seguridad y la privacidad. No declares operativa una integración sin prueba en un entorno configurado. Informa los archivos modificados, las reglas corregidas, las contradicciones pendientes y las validaciones realizadas.

## Contrato tipográfico

El sistema tipográfico global es un contrato de diseño. Times New Roman es la única familia autorizada para headings; `Times, serif` son fallbacks técnicos de plataforma, no familias alternativas de diseño. DM Sans es la única familia autorizada para cuerpo e interfaz. Los únicos pesos globales permitidos son 300, 400 y 500; 600, 700, 800, 900, `bold` y `bolder` están prohibidos. Excepción decorativa de `/servicios`: se autoriza Caveat únicamente para los captions manuscritos de piezas visuales tipo polaroid de `src/app/servicios/page.tsx`. Debe cargarse mediante `next/font/google`, con peso 400 y subset `latin`, utilizando únicamente la clase generada localmente, sin exponer una variable CSS global. Su uso debe quedar combinado con `.captionManuscrito`. Caveat no forma parte del sistema tipográfico global y no puede utilizarse en headings, cuerpo, navegación, botones, formularios, módulos, listas, otras páginas ni otros elementos de interfaz. Cualquier ampliación futura requiere aprobación explícita. Fuera de esta excepción, ningún agente puede incorporar otra familia, peso o archivo de fuente sin aprobación expresa del responsable, ni usar overrides tipográficos locales que evadan el sistema global. Ejecuta la validación tipográfica junto con las validaciones autorizadas que correspondan al alcance.
